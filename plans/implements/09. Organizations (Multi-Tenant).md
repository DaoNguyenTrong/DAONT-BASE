# Plan: Organizations (Multi-Tenant)

## Context

Hiện tại hệ thống là single-user/single-account model (`authentication.md`: "No multi-tenancy, no admin/global role"). Plan này thêm khái niệm **Organization (tenant)**: một account có thể thuộc nhiều organization, mỗi phiên đăng nhập chỉ hoạt động trong **một** organization tại một thời điểm.

Kiến trúc đã thống nhất qua thảo luận:

- **Shared-schema, row-level tenant** — một `Organization` + bảng nối `OrganizationMember` (Account ↔ Organization + role), không tách DB/schema theo tenant.
- **JWT mang `OrganizationId` claim** — session gắn với 1 tenant tại 1 thời điểm. Đổi tenant gọi `POST /api/auth/switch-organization` để lấy cặp token mới, **không** cần logout/login lại bằng credentials.
- **Không dùng header để xác định tenant** — client không tự khai báo tenant qua `X-Organization-Id`; claim trong JWT đã được ký, tin được ngay không cần tra DB mỗi request.
- **Vẫn verify lại mỗi request** (để bắt kịp revoke ngay, không chờ access token hết hạn) — qua `ITenantAccessService`, cache bằng `ICacheService` hiện có (`MemoryCacheService`, TTL ngắn). Chấp nhận được vì hệ thống chạy **single instance** — không cần Redis/distributed cache để đồng bộ invalidate giữa nhiều instance.

## Scope

**Trong phạm vi plan này (nền tảng backend):**

- Entity `Organization`, `OrganizationMember` + CRUD tối thiểu (create org, list org của tôi, list/add/remove member, đổi role).
- JWT org-scoping: claim, switch-organization endpoint, refresh giữ nguyên tenant.
- Per-request tenant access check + cache + invalidation.

**Ngoài phạm vi (follow-up phase riêng, không làm trong plan này):**

- Frontend UI (org switcher, trang quản lý member, luồng onboarding chọn/tạo org sau khi đăng ký).
- Invite-by-email (hiện tại add member yêu cầu account đã tồn tại, tra theo email/username).
- Áp `OrganizationId` + EF global query filter lên các entity nghiệp vụ tương lai (hiện chưa có entity nào cần tenant-scope ngoài chính `OrganizationMember`) — phần "Design Decisions" bên dưới có ghi pattern để dùng khi cần.
- Role/permission chi tiết theo action — v1 chỉ có 3 role cứng (Owner/Admin/Member), Admin trở lên mới được quản lý member.

### New — `backend/src/StarterKit.Domain/Entities/Organization.cs`

```csharp
using StarterKit.Domain.Exceptions;

namespace StarterKit.Domain.Entities;

public record OrganizationParams(string Name, string Slug, bool Status = true);

public sealed class Organization : BaseEntity<Guid>
{
    private Organization()
    {
    }

    public static Organization Create(OrganizationParams p)
    {
        Organization organization = new()
        {
            Id = IdGenerator.NewUuidV7()
        };
        organization.Update(p);
        return organization;
    }

    public string Name { get; private set; } = string.Empty;

    public string Slug { get; private set; } = string.Empty;

    public bool Status { get; private set; } = true;

    public void Update(OrganizationParams p)
    {
        if (string.IsNullOrWhiteSpace(p.Name))
        {
            throw new DomainException(DomainMessages.OrganizationNameRequired);
        }

        if (string.IsNullOrWhiteSpace(p.Slug))
        {
            throw new DomainException(DomainMessages.OrganizationSlugRequired);
        }

        Name = p.Name.Trim();
        Slug = p.Slug.Trim().ToLowerInvariant();
        Status = p.Status;
    }

    public void Deactivate() => Status = false;
}
```

### New — `Services/Organizations/` (DTOs + interface + implementation)

```csharp
public record OrganizationDto(Guid Id, string Name, string Slug, bool Status, OrganizationRole MyRole);
public record OrganizationMemberDto(Guid AccountId, string AccountName, string Email, OrganizationRole Role);
public record CreateOrganizationRequest(string Name, string Slug);
public record AddMemberRequest(string Email, OrganizationRole Role);
public record UpdateMemberRoleRequest(OrganizationRole Role);

public interface IOrganizationService
{
    Task<OrganizationDto> CreateAsync(CreateOrganizationRequest request, CancellationToken ct);
    Task<IReadOnlyList<OrganizationDto>> ListMineAsync(CancellationToken ct);
    Task<IReadOnlyList<OrganizationMemberDto>> GetMembersAsync(Guid organizationId, CancellationToken ct);
    Task AddMemberAsync(Guid organizationId, AddMemberRequest request, CancellationToken ct);
    Task UpdateMemberRoleAsync(Guid organizationId, Guid accountId, UpdateMemberRoleRequest request, CancellationToken ct);
    Task RemoveMemberAsync(Guid organizationId, Guid accountId, CancellationToken ct);
}
```

Điểm quan trọng trong `OrganizationService`:

- `CreateAsync`: tạo `Organization` + `OrganizationMember(Role = Owner)` cho account hiện tại trong **cùng 1 transaction** (2 `AddAsync` rồi 1 `SaveChangesAsync` — `UnitOfWork` hiện tại không wrap explicit transaction, nhưng cả hai insert nằm trong cùng 1 `SaveChangesAsync` call nên đã atomic ở mức DB). Không tự động switch token ở bước này — client tạo xong org thì gọi `switch-organization` để lấy token mới (giữ 1 endpoint = 1 trách nhiệm, giống style hiện tại).
- `AddMemberAsync`/`UpdateMemberRoleAsync`/`RemoveMemberAsync`: yêu cầu caller hiện tại có role Owner/Admin trong org đó (tra `OrganizationMember` của `currentUserService.UserId` — check thủ công trong service, **không** dùng policy-based `[Authorize]` mới vì v1 chỉ cần 1 quy tắc đơn giản này). Không đủ quyền → `ForbiddenException`.
- `RemoveMemberAsync`/role vừa đổi xong → gọi `tenantAccessService.InvalidateMemberAsync(...)` ngay để access bị revoke có hiệu lực tức thì, không chờ TTL cache.
- Không cho remove Owner cuối cùng của org (tránh org mồ côi) — validate trong service trước khi `Deactivate()`.

### Modify — `Services/Auth/AuthService.cs`

- `IssueTokensAsync` thêm tham số `Guid? organizationId`, truyền vào `jwtTokenService.GenerateAccessToken(account, organizationId)` và lưu vào `RefreshToken.OrganizationId`.
- `LoginAsync` / `VerifyEmailAsync` / `ExternalLoginAsync`: sau khi xác thực account, resolve `organizationId` = org duy nhất account đang là active member (nếu account chỉ thuộc đúng 1 org — auto-select cho gọn UX); nếu 0 hoặc ≥2 org, `organizationId = null` (token không có tenant, frontend sẽ hiện màn chọn/tạo org — nằm ở phase frontend follow-up).
- `RefreshTokenAsync`: **không** resolve lại tenant — dùng đúng `storedToken.OrganizationId` để giữ nguyên tenant của phiên, đồng thời gọi lại `tenantAccessService.HasActiveAccessAsync` (nếu `OrganizationId` khác null) trước khi cấp access token mới — phòng trường hợp bị revoke access giữa 2 lần refresh nhưng access token cũ chưa kịp hết hạn.
- Method mới `SwitchOrganizationAsync`:

```csharp
public async Task<AuthResult> SwitchOrganizationAsync(
    Guid organizationId, string? deviceInfo, string? ipAddress, CancellationToken cancellationToken)
{
    Guid accountId = GetCurrentAccountId();

    OrganizationMember? member = await unitOfWork.Repository<OrganizationMember, Guid>()
        .FirstOrDefaultAsync(
            m => m.OrganizationId == organizationId && m.AccountId == accountId && m.IsActive,
            cancellationToken);

    Organization? organization = member is null
        ? null
        : await unitOfWork.Repository<Organization, Guid>().GetByIdAsync(organizationId, cancellationToken);

    if (member is null || organization is null || !organization.Status)
    {
        throw new ForbiddenException(ApplicationMessages.OrganizationAccessDenied);
    }

    Account account = await unitOfWork.Repository<Account, Guid>().GetByIdAsync(accountId, cancellationToken)
        ?? throw new UnauthorizedException(ApplicationMessages.AuthenticatedUserRequired);

    return await IssueTokensAsync(account, organizationId, deviceInfo, ipAddress, true, DateTime.UtcNow, cancellationToken);
}
```

Đi thẳng DB (không qua `ITenantAccessService` cache) vì đây là hành động chủ động đổi tenant — cần dữ liệu tươi nhất, không chấp nhận độ trễ TTL.

### New — `Services/Auth/TenantAccessService.cs`

```csharp
internal sealed class TenantAccessService(
    IUnitOfWork unitOfWork,
    ICacheService cacheService,
    IOptions<TenantAccessSettings> options) : ITenantAccessService
{
    private readonly TenantAccessSettings settings = options.Value;

    private static string CacheKey(Guid organizationId, Guid accountId) =>
        $"tenant-access:{organizationId}:{accountId}";

    public Task<bool> HasActiveAccessAsync(
        Guid accountId, Guid organizationId, CancellationToken cancellationToken = default)
    {
        return cacheService.GetOrSetAsync(
            CacheKey(organizationId, accountId),
            async ct =>
            {
                OrganizationMember? member = await unitOfWork.Repository<OrganizationMember, Guid>()
                    .FirstOrDefaultAsync(
                        m => m.OrganizationId == organizationId && m.AccountId == accountId && m.IsActive, ct);

                if (member is null)
                {
                    return false;
                }

                Organization? organization = await unitOfWork.Repository<Organization, Guid>()
                    .GetByIdAsync(organizationId, ct);

                return organization is { Status: true };
            },
            TimeSpan.FromSeconds(settings.CacheTtlSeconds),
            cancellationToken);
    }

    public Task InvalidateMemberAsync(
        Guid organizationId, Guid accountId, CancellationToken cancellationToken = default) =>
        cacheService.RemoveAsync(CacheKey(organizationId, accountId), cancellationToken);

    public Task InvalidateOrganizationAsync(
        Guid organizationId, CancellationToken cancellationToken = default) =>
        cacheService.RemoveByPrefixAsync($"tenant-access:{organizationId}:", cancellationToken);
}
```

**Thứ tự trong cache key là `{organizationId}:{accountId}`, không phải ngược lại** — để `RemoveByPrefixAsync` invalidate được toàn bộ member của 1 org khi org bị deactivate (prefix theo orgId). Nếu đảo ngược thứ tự sẽ chỉ prefix-invalidate được theo account, không invalidate được theo org.

## API Layer (`StarterKit.API`)

### New — `Middleware/TenantAccessMiddleware.cs`

```csharp
public sealed class TenantAccessMiddleware(RequestDelegate next)
{
    public async Task InvokeAsync(
        HttpContext context,
        ICurrentUserService currentUserService,
        ICurrentTenantProvider currentTenantProvider,
        ITenantAccessService tenantAccessService)
    {
        if (context.User.Identity?.IsAuthenticated != true)
        {
            await next(context);
            return;
        }

        Guid? organizationId = currentTenantProvider.OrganizationId;

        if (organizationId is null)
        {
            // Token chưa gắn tenant (mới đăng ký, chưa tạo/chọn org) — để endpoint tự quyết có yêu cầu tenant hay không.
            await next(context);
            return;
        }

        if (!Guid.TryParse(currentUserService.UserId, out Guid accountId) ||
            !await tenantAccessService.HasActiveAccessAsync(accountId, organizationId.Value, context.RequestAborted))
        {
            await WriteProblemAsync(context); // 403, ProblemDetails — theo đúng format UserTimeZoneMiddleware đang dùng
            return;
        }

        await next(context);
    }
}
```

## Key Design Decisions

| Quyết định | Lý do |
|---|---|
| Tenant xác định qua JWT claim (`org_id`), không qua header | Header là input client tự khai, không tin được — buộc phải tra DB mỗi request để verify dù thế nào; claim đã ký sẵn nên tin ngay, per-request check chỉ còn là lớp revoke nhanh (cached), không phải lớp xác thực chính |
| Đổi tenant = endpoint `switch-organization` phát token mới, không bắt logout | Chuẩn UX của GitHub/Linear/Slack khi đổi workspace — không nhập lại mật khẩu; vẫn đảm bảo mỗi token chỉ chứa đúng 1 tenant tại 1 thời điểm |
| Cache key `tenant-access:{organizationId}:{accountId}` (org trước, account sau) | Cho phép `RemoveByPrefixAsync` invalidate toàn bộ member khi 1 org bị deactivate — đảo thứ tự sẽ mất khả năng này |
| Refresh token lưu lại `OrganizationId` lúc issue, `RefreshTokenAsync` không resolve lại tenant | Nếu resolve lại (ví dụ theo "org đầu tiên tìm thấy"), user có thể bị đổi tenant ngầm giữa 2 lần refresh mà không chủ động switch — vi phạm nguyên tắc "1 session = 1 tenant" |
| Dùng `ICacheService`/`MemoryCacheService` có sẵn (single-instance), không đổi sang Redis | Xác nhận với user: hệ thống hiện chạy single instance — TTL ngắn (60s) đủ làm bound chấp nhận được; multi-instance sẽ cần distributed cache để `RemoveByPrefixAsync` invalidate đồng bộ across instances (ghi chú lại làm follow-up nếu sau này scale ra nhiều instance) |
| Chưa áp EF global query filter theo `OrganizationId` | Chưa có entity nghiệp vụ nào khác cần tenant-scope ngoài `OrganizationMember` tự thân — thêm filter bây giờ là đầu cơ cho nhu cầu chưa xuất hiện; pattern (thêm interface `ITenantScoped { Guid OrganizationId }`, loop `modelBuilder.Model.GetEntityTypes()` áp `HasQueryFilter` bằng reflection) để dùng khi entity đầu tiên cần nó |
| Role check thủ công trong `OrganizationService`, không dùng policy-based `[Authorize]` | v1 chỉ có 1 quy tắc duy nhất (Admin/Owner mới quản lý member) — thêm 1 authorization policy mới cho đúng 1 chỗ dùng là over-engineering ở bước này |
| Không cho remove Owner cuối cùng của 1 org | Tránh org mồ côi không ai quản lý được (không có admin/global role nào bypass được theo `authentication.md`) |
