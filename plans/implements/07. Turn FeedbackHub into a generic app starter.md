# Turn FeedbackHub into a generic app starter (StarterKit)

## Context

This repo (`DAONT-BASE`) was built as "Feedback Hub" — a multi-tenant feedback-collection SaaS — but per `README.md` the actual feedback product (embed widget, feedback submission, dashboard workflow) was **never implemented**. What exists today is already a generic multi-tenant SaaS foundation: Auth (email+password, Google login), Tenant/Membership, ApiKey, AuditLog, File storage, SystemSettings, Account/Profile. The user wants to repurpose this foundation as a clean, reusable app-starter template for future projects, dropping the FeedbackHub-specific naming and the parts of the foundation they've decided not to carry forward.

Decisions already locked in with the user:
- **Drop multi-tenancy** entirely (Tenant/TenantMembership/TenantRole/`X-Tenant-Id`) → simplify to single-user/account model.
- **Keep**: Google login, ApiKey, AuditLog, Files (storage), SystemSettings, Account/Profile, email+password auth.
- **New name: `StarterKit`** (replaces `FeedbackHub`/`FEEDBACK-HUB`/`feedback-hub` everywhere).
- **Squash the 7 existing EF migrations** into a single clean initial migration (no need to preserve FeedbackHub-era schema history).

Three Explore agents mapped the full surface (backend tenancy coupling, frontend tenancy/rename surface, docs/config/tooling rename surface) — findings are folded into the phases below. Key takeaways from that mapping:
- Multi-tenancy was bolted on as an **isolated vertical slice** (own entity files, own service, own controller, own middleware, own DI lines) — zero coupling into Auth/Account/ApiKey/AuditLog/Files/SystemSettings. Removal is low-risk.
- Frontend has **zero tenant code** and is **already generically named** ("App Starter" in `index.html`/locales) — only `frontend/package.json` and `frontend/README.md` need renaming.
- `frontend/src/lib/feedback.ts` / `feedback-naive.ts` are a UI toast/dialog utility — name collision with "FeedbackHub" only, not a business-domain leak. Leave alone.
- No `docker-compose.yml`/`Dockerfile` exists anywhere — a real gap for a "clone and run" starter, given email verification is mandatory and there's no seeder (per `.claude/decisions.md`, a dev-bypass was explicitly rejected in favor of "use Mailpit locally" — that recommendation was never actually wired up).

One incidental note from the docs/config exploration: the harness flagged that one file's content pattern-matched as "instruction-shaped" (likely a routine safety heuristic tripped by wording inside `.claude/settings.json` or similar) and neutralized it before returning the summary — nothing suspicious surfaced in the actual content reported (just normal hook/permission config). Flagging it here for transparency, not as an actual finding.

## Phase A — Remove multi-tenancy (backend)

- `Domain/Tests/Entities/{TenantTests,TenantMembershipTests}.cs`
- `Application/Common/Interfaces/{ICurrentTenantService,ITenantContextResolver}.cs`
- `Application/Services/Tenants/` (whole folder: `TenantService.cs`, `ITenantService.cs`, DTOs, request records)
- `Application.Tests/Services/Tenants/TenantServiceTests.cs`
- `Infrastructure/Services/{CurrentTenantService,TenantContextResolver}.cs`
- `Infrastructure/Persistence/Configurations/{TenantConfiguration,TenantMembershipConfiguration}.cs`
- `API/Middleware/TenantMiddleware.cs`
- `API/Controllers/TenantsController.cs`

Edit (mixed files — remove only the tenant-specific parts):
- `Domain/Exceptions/DomainMessages.cs` — remove `TenantNameRequired`/`TenantIdRequired`/`TenantRoleRequired`.
- `Application/Common/Mappings/EntityMapper.cs` — remove the `Tenant`/`TenantMembership` mapping methods + the `using ...Services.Tenants;`. Keep all Account mapping methods.
- `Application/DependencyInjection.cs` — remove the `ITenantService` DI line + using.
- `Application/Resources/Messages.resx` + `Messages.en.resx` — remove tenant-only keys (`TenantNameRequired`, `TenantIdRequired`, `TenantRoleRequired`, `OnlyTenantOwnerCanInvite/Remove/Transfer`).
- `Application/ApplicationMessages.cs` — remove tenant-only constants. **Before deleting `AuthenticatedUserRequired`, grep whether `AuthService`/`AccountService` reuse it** — if reused, keep it.
- `Infrastructure/Persistence/AppDbContext.cs` — remove `DbSet<Tenant>` / `DbSet<TenantMembership>`.
- `Infrastructure/Persistence/PersistenceExtensions.cs` — remove the 2 tenant DI registration lines only.
- `API/Program.cs` — remove `app.UseMiddleware<TenantMiddleware>();`.

Also delete tenancy-specific docs made irrelevant by this removal: `shared/docs/api/api-tenants.md`, `shared/docs/api/integration-tenants.md`.

Build (`dotnet build backend/FEEDBACK-HUB.sln --no-restore -m:1`) after this phase to catch anything the grep-based mapping missed before moving on.

## Phase B — Squash migrations

After Phase A compiles clean: delete all 7 existing migration files + their `.Designer.cs` + `AppDbContextModelSnapshot.cs` under `Infrastructure/Migrations/`, then run `dotnet ef migrations add InitialCreate --project backend/src/FeedbackHub.Infrastructure --startup-project backend/src/FeedbackHub.API` (paths get renamed in Phase C — running this before or after the rename both work, but simplest is to do it here on the still-`FeedbackHub`-named paths, then let Phase C's rename sweep pick up the new migration file's namespace along with everything else). Requires a local Postgres reachable via `appsettings.Development.json`/env — if none is running yet, this step depends on Phase E's `docker-compose` being available first; sequence Phase E before this if no dev Postgres exists today.

## Phase C — Rename FeedbackHub → StarterKit

Mechanical, repo-wide, case-variant-aware (`FeedbackHub`→`StarterKit`, `FEEDBACK-HUB`→`STARTERKIT` or `StarterKit` for the `.sln` — recommend just `StarterKit.sln`, simpler than replicating the old hyphen-caps split, `feedback-hub`→`starter-kit`, `Feedback Hub`→`Starter Kit`):

- **Backend**: rename 4 project folders + `.csproj` files (`FeedbackHub.Domain`→`StarterKit.Domain`, etc.), `backend/FEEDBACK-HUB.sln`→`backend/StarterKit.sln`, all C# namespace declarations/usings, test project folders (`FeedbackHub.Domain.Tests`→`StarterKit.Domain.Tests`, `FeedbackHub.Application.Tests`→`StarterKit.Application.Tests`, including `TestSupport/`), project references inside every `.csproj`.
- **Config values** (`appsettings.Example.json`): `ConnectionStrings.DefaultConnection` DB name `FeedbackHub_api`→`StarterKit_api`, `JwtSettings.Issuer`/`Audiences`, `EmailSettings.FromName`.
- **Frontend**: `frontend/package.json` name, `frontend/README.md` title + intro line.
- **CI**: `.github/workflows/release.yml` (sln path, publish path).
- **`.claude/` tooling**: `rules/{architecture,localization,commands,api-contract}.md`, `hooks/pre-task-reminder.sh`, `workflows/localization-sync-audit.js`, `skills/clean-architecture-review/{SKILL.md,violation-patterns.md}`, `skills/crud-entity/SKILL.md`, `decisions.md` header line. Also fix the stale `gitnexus://repo/FEEDBACK-HUB/...` resource URIs in `clean-architecture-review/SKILL.md` — GitNexus's registered repo name tracks the folder (`DAONT-BASE`, already updated per the current `CLAUDE.md`), not the code namespace, so these should point at `DAONT-BASE`, not `StarterKit`.
- **Root docs**: `AGENTS.md`, `CLAUDE.md` (sln path references).
- After the code/config rename compiles and passes tests: re-run `npx gitnexus analyze` to refresh the index against the new namespaces, then `gitnexus_detect_changes()` to confirm only the expected symbols moved.

Skip renaming inside `plans/**` (historical dev logs, e.g. `plans/v1/phase 1. Tenancy Core.md`) — see Phase D, most of these get deleted/archived anyway since they document the removed tenancy feature or a one-time import event.

For the "`TenantMembership` role validation: never check `== default` on an enum" entry — reframe generically (drop the now-deleted `TenantMembership` specifics, keep the lesson: "`== default` is never a valid required-check for an enum whose first member is the meaningful default — use `Enum.IsDefined`") since it's a real, reusable pitfall.

## Phase E — DX gap: local dev bootstrap

Add what's needed for "clone and run" to actually work, given email verification is mandatory with no seeder:
- Add root `docker-compose.yml`: Postgres service (matching `appsettings.Example.json`'s default DB name/credentials post-rename) + Mailpit service (SMTP on `1025`, web UI on `8025` — matches `EmailSettings.Host/Port` defaults already in `appsettings.Example.json`). This fulfills the recommendation already on record in `decisions.md` ("recommend Mailpit/MailHog for local dev") that was never actually wired up — no change to the mandatory-verification behavior itself, just makes the documented workaround real.
- Update the new `README.md` (Phase D) with a "Getting started" section: `docker compose up -d` → `dotnet ef database update` → `dotnet run` → register → check `localhost:8025` for the verification email.
