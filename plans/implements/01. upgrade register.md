# Nâng cấp Register (Backend): Email verification + Social login

## Context

Audit trước đó phát hiện: `POST /api/auth/register` hiện tại tạo account và auto-login ngay lập tức, không có bước xác thực email, và không hề có social login dù `.claude/decisions.md` từng nhắc tới 3 provider (Google/Microsoft/GitHub) rồi quyết định hoãn ("Social login để sau MVP"). User giờ muốn làm ngay, backend trước, và đã chốt:

1. **Email verification bắt buộc** — register KHÔNG auto-login nữa; phải verify email xong mới login được. SMTP dùng thật (không có đường tắt auto-confirm cho dev).
2. **Social login theo Option B** — FE tự lấy credential từ SDK provider (id_token/code), POST lên BE; BE verify credential với provider rồi issue JWT. BE không tự redirect sang provider.
3. Đây là đảo ngược quyết định "Social login để sau MVP, drop bootstrap admin" đã log — sẽ ghi đè lại quyết định mới trong `.claude/decisions.md` sau khi implement xong.

Vì register không còn auto-login, và chưa có UI/seeder nào khác tạo account — flow register → verify email (qua SMTP thật) → login chính là con đường bootstrap duy nhất của hệ thống. Không cần cơ chế tắt riêng cho dev, miễn SMTP được cấu hình đúng (khuyến nghị dùng Mailpit/MailHog cho local dev — SMTP thật, chỉ là không gửi ra ngoài internet).

Reuse chính: `Account`/`RefreshToken` entity pattern (`BaseEntity<Guid>` + private ctor + `Create`/factory), `ApiKey`'s SHA256-hash-not-plaintext precedent (`ApiKeyService.cs`), `AuthExtensions.cs`'s fail-fast settings validation pattern, `EntityMapper` (Mapperly) DTO mapping, `AuthServiceTests`'s NSubstitute fixture pattern.

## Phase 1 — Email verification

### Domain (`FeedbackHub.Domain`)
- `Entities/Account.cs`: thêm `EmailConfirmed` (bool, private set, default `false`) + method `ConfirmEmail()`. Migration sẽ backfill row cũ (nếu có) thành `true`.
- `Entities/EmailVerificationToken.cs` (mới, `BaseEntity<Guid>`, theo pattern `ApiKey.cs`/`RefreshToken.cs`): `AccountId`, `TokenHash` (SHA256 hex, KHÔNG lưu raw token — khác với `RefreshToken` đang lưu plaintext, đây là nợ kỹ thuật cũ không copy sang), `ExpiresAt`, `ConsumedAt`. Static `Create(Guid accountId, string tokenHash, DateTime expiresAt)` + method `Consume()`.
- `DomainMessages.cs`: thêm `EmailVerificationTokenRequired`, `EmailVerificationTokenExpiryFuture` (theo đúng pattern các dòng `RefreshToken*` hiện có).

### Application (`FeedbackHub.Application`)
- `Common/Interfaces/IEmailSender.cs` (mới): `Task SendAsync(string toEmail, string subject, string htmlBody, CancellationToken ct)`.
- `Common/Settings/EmailSettings.cs` (mới, theo pattern `StorageSettings.cs`): `Host`, `Port`, `Username`, `Password`, `FromAddress`, `FromName`, `UseSsl` (bool), `VerificationTokenExpiryHours` (default 24), `FrontendBaseUrl` (dùng để build link `{FrontendBaseUrl}/verify-email?token=...`).
- `Services/Auth/IAuthService.cs`: đổi `RegisterAsync` để KHÔNG trả `AuthResult` nữa (không auto-login) — trả `Task RegisterAsync(...)` hoặc 1 DTO nhẹ kiểu `RegisterResult(Guid AccountId, string Email)`. Thêm `Task<AuthResult> VerifyEmailAsync(string token, string? deviceInfo, string? ipAddress, CancellationToken ct)` (verify xong thì issue token luôn — auto-login sau verify, giống hành vi cũ của register), `Task ResendVerificationEmailAsync(string email, CancellationToken ct)`.
- `Services/Auth/AuthService.cs`:
  - `RegisterAsync`: giữ nguyên uniqueness check (`EnsureUniqueAccountAsync`) + tạo `Account`, nhưng KHÔNG gọi `IssueTokensAsync` nữa. Thay vào đó sinh raw token (`RandomNumberGenerator`, theo `ApiKeyService.GenerateRawKey()` pattern), hash SHA256, lưu `EmailVerificationToken`, gọi `IEmailSender.SendAsync(...)`.
  - `LoginAsync`: thêm check `account.EmailConfirmed` — nếu `false`, throw `UnauthorizedException(ApplicationMessages.EmailNotConfirmed)` trước khi verify password (hoặc sau — quyết định UX: sau verify password để không lộ việc account có tồn tại hay chưa verify; khuyến nghị check sau khi password đã verify đúng).
  - `VerifyEmailAsync`: hash token nhận được, tìm `EmailVerificationToken` theo `TokenHash` còn active (`ConsumedAt == null && ExpiresAt > now`), nếu không thấy → `UnauthorizedException`. Nếu thấy: `ConfirmEmail()` trên account, `Consume()` trên token, rồi gọi `IssueTokensAsync` (tái dùng y nguyên private method có sẵn) để login luôn.
  - `ResendVerificationEmailAsync`: tìm account theo email, nếu đã confirmed thì throw `ConflictException(EmailAlreadyConfirmed)`, ngược lại revoke token cũ (nếu muốn) + sinh token mới + gửi lại.
- `Services/Auth/RegisterRequest.cs`, thêm `VerifyEmailRequest.cs` (`string Token`), `ResendVerificationRequest.cs` (`string Email`, có `[EmailAddress]`).
- `ApplicationMessages.cs`: thêm `EmailNotConfirmed`, `EmailVerificationTokenInvalidOrExpired`, `EmailAlreadyConfirmed`.

### Infrastructure (`FeedbackHub.Infrastructure`)
- `Services/EmailExtensions.cs` (mới, theo pattern `AuthExtensions.AddJwtAuthentication`/`StorageExtensions.AddStorage`): `internal static IServiceCollection AddEmail(this IServiceCollection, IConfiguration)` — bind `EmailSettings`, fail-fast validate Host/Port/FromAddress không rỗng (theo đúng style throw `InvalidOperationException` của `AddJwtAuthentication`), đăng ký `IEmailSender -> SmtpEmailSender`.
- `Services/SmtpEmailSender.cs` (mới): dùng **MailKit** (`MailKit.Net.Smtp.SmtpClient` + `MimeKit.MimeMessage`) — thêm package `MailKit` vào `FeedbackHub.Infrastructure.csproj`. Đây là implementation `ILogger<T>` đầu tiên thật sự log trong Infrastructure — log lỗi gửi mail ở mức `LogError` nhưng KHÔNG nuốt exception (để `ExceptionHandlingMiddleware` xử lý thống nhất).
- `DependencyInjection.cs`: thêm `services.AddEmail(configuration);` vào chuỗi `AddInfrastructure`.
- `Persistence/Configurations/EmailVerificationTokenConfiguration.cs` (mới, theo pattern `ApiKeyConfiguration.cs`): table `email_verification_tokens`, unique index trên `TokenHash`, FK tới `Account` (`OnDelete(DeleteBehavior.Cascade)`, theo pattern `TenantMembershipConfiguration`).
- `Persistence/Configurations/AccountConfiguration.cs`: thêm mapping cho `EmailConfirmed` (`HasDefaultValue(false)`, `IsRequired`).
- `Persistence/AppDbContext.cs`: thêm `DbSet<EmailVerificationToken> EmailVerificationTokens => Set<EmailVerificationToken>();` (chèn đúng vị trí alphabet), thêm `EmailVerificationToken` vào `AuditExcludedEntityTypes` (giống `RefreshToken` — token ngắn hạn, không cần audit log).
- Migration mới: `dotnet ef migrations add AddEmailVerificationTokenAndAccountEmailConfirmed --project backend/src/FeedbackHub.Infrastructure --startup-project backend/src/FeedbackHub.API`. Sau khi generate, sửa tay migration để `UPDATE accounts SET email_confirmed = true` (backfill data cũ) trước khi set cột về `NOT NULL DEFAULT false` cho row mới — hoặc đơn giản là set default `true` ở cấp DB migration rồi đổi default app-level về `false` sau (bàn kỹ khi viết migration, vì `AccountConfiguration` hiện chưa set `HasDefaultValue` nào tương tự cần đối chiếu).

### API (`FeedbackHub.API`)
- `Controllers/AuthController.cs`:
  - `Register` action: đổi response — không còn set cookie/trả `LoginResponse` nữa, trả `202 Accepted` hoặc `200 OK` với thông báo "check your email" (không lộ thông tin nhạy cảm).
  - Thêm `POST api/auth/verify-email` (`VerifyEmailRequest`) → gọi `VerifyEmailAsync`, set cookie + trả `LoginResponse` giống hệt `Login`/cách `SetAuthCookies` hiện có (tái dùng private method).
  - Thêm `POST api/auth/resend-verification` (`ResendVerificationRequest`) → `204 NoContent`.
- **Rate limiting**: dùng `Microsoft.AspNetCore.RateLimiting` (built-in .NET, không cần package thêm). Đăng ký `builder.Services.AddRateLimiter(...)` trong `Program.cs` (cạnh các `builder.Services.Add...` khác, trước `builder.Build()`), định nghĩa policy IP-based (fixed window, vd 5 request/phút) áp cho `register`, `resend-verification`, `login` qua `.RequireRateLimiting("auth")` trên action hoặc group. Middleware `app.UseRateLimiter()` chèn sau `app.UseCors()` và trước `app.UseAuthentication()` trong pipeline hiện tại.

### Localization
- `Messages.resx` (vi, default) + `Messages.en.resx`: thêm key cho toàn bộ message const mới ở trên (`EmailNotConfirmed`, `EmailVerificationTokenInvalidOrExpired`, `EmailAlreadyConfirmed`, `EmailVerificationTokenRequired`, `EmailVerificationTokenExpiryFuture`) — theo đúng convention `localization.md`.

### Config
- `appsettings.Example.json`: thêm block `"EmailSettings"` (Host/Port/Username/Password/FromAddress/FromName/UseSsl/VerificationTokenExpiryHours/FrontendBaseUrl) ngay sau `StorageSettings`, theo pattern hiện có.
- Khuyến nghị dev setup: chạy Mailpit qua docker (`docker run -p 1025:1025 -p 8025:8025 axllent/mailpit`) trỏ `EmailSettings:Host=localhost;Port=1025`, xem email ở `http://localhost:8025` — SMTP thật 100%, không cần internet/tài khoản email thật.

### Tests
- `AuthServiceTests.cs`: mở rộng `Fixture` với `IRepository<EmailVerificationToken, Guid>` substitute + `IEmailSender` substitute. Test case mới: `RegisterAsync_CreatesUnconfirmedAccountAndSendsEmail_DoesNotIssueTokens`, `LoginAsync_EmailNotConfirmed_ThrowsUnauthorized`, `VerifyEmailAsync_ValidToken_ConfirmsAndIssuesTokens`, `VerifyEmailAsync_ExpiredOrConsumedToken_ThrowsUnauthorized`, `ResendVerificationEmailAsync_AlreadyConfirmed_ThrowsConflict`.

## Phase 2 — Social login (Google trước, Microsoft/GitHub fast-follow cùng abstraction)

### Domain
- `Entities/ExternalLogin.cs` (mới, `BaseEntity<Guid>`): `AccountId`, `Provider` (string: `"Google"|"Microsoft"|"GitHub"`), `ProviderUserId`, `Email` (snapshot). Static `Create(...)`.
- `DomainMessages.cs`: thêm `ExternalLoginProviderRequired`, `ExternalLoginProviderUserIdRequired`.

### Application
- `Common/Interfaces/IExternalAuthProvider.cs` (mới): `string ProviderName { get; }`, `Task<ExternalUserInfo> ValidateAsync(string credential, CancellationToken ct)` — trả `record ExternalUserInfo(string ProviderUserId, string Email, string? Name)`.
- `Services/Auth/IAuthService.cs`: thêm `Task<AuthResult> ExternalLoginAsync(string provider, string credential, string? deviceInfo, string? ipAddress, CancellationToken ct)`.
- `Services/Auth/AuthService.cs` — `ExternalLoginAsync`:
  1. Resolve `IExternalAuthProvider` theo tên provider (inject `IEnumerable<IExternalAuthProvider>`, chọn theo `ProviderName`).
  2. `ValidateAsync(credential)` → lấy `ExternalUserInfo`.
  3. Tìm `ExternalLogin` theo `(Provider, ProviderUserId)` — có thì lấy `Account` liên kết, login luôn.
  4. Không có: tìm `Account` theo `Email`. Nếu tồn tại VÀ `EmailConfirmed == true` → auto-link (tạo `ExternalLogin` mới trỏ account đó). Nếu tồn tại nhưng `EmailConfirmed == false` → throw `ConflictException` yêu cầu verify email trước. Nếu không tồn tại → tạo `Account` mới với `EmailConfirmed = true` (provider đã verify email hộ), `Username` sinh từ local-part của email + suffix số nếu trùng (hàm helper mới, check unique qua repository trước khi gán), không set `PasswordHash`.
  5. `IssueTokensAsync` (tái dùng).
- `ApplicationMessages.cs`: thêm `ExternalLoginEmailNotConfirmed`, `ExternalLoginProviderNotSupported`.

### Infrastructure
- `Services/GoogleAuthProvider.cs` (mới, implement `IExternalAuthProvider`): dùng package `Google.Apis.Auth` (`GoogleJsonWebSignature.ValidateAsync(idToken, settings)` — validate signature/audience/issuer, không cần secret). Cấu hình `ClientId` qua `ExternalAuthSettings`.
- `Common/Settings/ExternalAuthSettings.cs` (Application layer, theo pattern `EmailSettings`): `Google: { ClientId }`, để trống sẵn `Microsoft`/`GitHub` cho fast-follow.
- `Services/ExternalAuthExtensions.cs`: đăng ký `IExternalAuthProvider` cho Google (chỉ Google ở phase này), bind settings.
- `Persistence/Configurations/ExternalLoginConfiguration.cs`: unique index `(Provider, ProviderUserId)`, FK Account cascade.
- `AppDbContext.cs`: `DbSet<ExternalLogin>`.
- Migration mới: `AddExternalLoginEntity`.

### API
- `AuthController.cs`: thêm `POST api/auth/external/{provider}` (body: `{ credential: string }`) → `ExternalLoginAsync`, set cookie, trả `LoginResponse` như login/verify-email.
- Áp rate limit policy `"auth"` tương tự.

### Fast-follow (không làm trong đợt này, chỉ giữ đúng abstraction để thêm sau)
- Microsoft: `IExternalAuthProvider` mới validate id_token (JWT chuẩn) qua JWKS của Microsoft, tái dùng `Microsoft.IdentityModel.Tokens` đã có sẵn trong repo — không cần MSAL.
- GitHub: `IExternalAuthProvider` mới — GitHub là OAuth2 thuần (không có id_token) nên credential nhận từ FE là `code`; provider gọi `HttpClient` exchange code → access token → `GET https://api.github.com/user`. Cần `IHttpClientFactory` (chưa có tiền lệ nào trong repo, sẽ là lần đầu dùng `services.AddHttpClient(...)`).
- Set-password flow cho account tạo qua social (hiện `PasswordHash` nullable, không cần đổi entity) — không nằm trong scope 2 phase này.

### Tests
- `AuthServiceTests.cs` mở rộng: `ExternalLoginAsync_NewProviderUserId_CreatesAccountAndLinks`, `ExternalLoginAsync_ExistingLink_LogsIn`, `ExternalLoginAsync_EmailMatchesUnconfirmedAccount_ThrowsConflict`, `ExternalLoginAsync_EmailMatchesConfirmedAccount_AutoLinks`.
- 1 fake `IExternalAuthProvider` (test double) thay vì gọi Google thật.

## Quyết định cần log lại sau khi implement xong
