# Plan: Refresh Token Cleanup Background Service

## Context

Mỗi lần login, refresh, hay revoke đều tạo hoặc cập nhật row trong bảng `refresh_tokens`. Rows hết hạn (`ExpiresAt`) và rows đã revoke không bao giờ bị xóa — tích lũy vô thời hạn. Mặc dù `IsActive` filter giới hạn tác động với session list API, bảng ngày càng phình to và tốn chi phí index scan không cần thiết.

Giải pháp: `BackgroundService` chạy định kỳ (mỗi 24h theo mặc định), bulk-delete các tokens đã hết retention window bằng EF Core `ExecuteDeleteAsync` — không load rows vào memory.

## Files

### New: `backend/src/FeedbackHub.Application/Common/Settings/RefreshTokenCleanupSettings.cs`

Theo đúng pattern của `JwtSettings`, `CacheSettings`, v.v.:

```csharp
public sealed class RefreshTokenCleanupSettings
{
    public int IntervalHours { get; init; } = 24;
    public int RetentionDays { get; init; } = 7;
}
```

- **`IntervalHours`**: khoảng cách giữa các lần chạy.
- **`RetentionDays`**: giữ lại tokens trong N ngày sau khi chúng hết hạn hoặc bị revoke, để audit trail còn nhìn thấy các session gần đây trong ProfileDialog.

### New: `backend/src/FeedbackHub.Infrastructure/Services/RefreshTokenCleanupService.cs`

```csharp
public sealed class RefreshTokenCleanupService(
    IServiceScopeFactory scopeFactory,
    IOptions<RefreshTokenCleanupSettings> options,
    ILogger<RefreshTokenCleanupService> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        using PeriodicTimer timer = new(TimeSpan.FromHours(options.Value.IntervalHours));

        while (await timer.WaitForNextTickAsync(stoppingToken))
        {
            await RunCleanupAsync(stoppingToken);
        }
    }

    private async Task RunCleanupAsync(CancellationToken ct)
    {
        DateTime cutoff = DateTime.UtcNow.AddDays(-options.Value.RetentionDays);
        try
        {
            await using AsyncServiceScope scope = scopeFactory.CreateAsyncScope();
            AppDbContext context = scope.ServiceProvider.GetRequiredService<AppDbContext>();

            int deleted = await context.RefreshTokens
                .Where(t => t.ExpiresAt < cutoff ||
                            (t.RevokedAt != null && t.RevokedAt < cutoff))
                .ExecuteDeleteAsync(ct);

            if (deleted > 0)
                logger.LogInformation("Deleted {Count} expired/revoked refresh tokens.", deleted);
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            logger.LogError(ex, "Refresh token cleanup failed.");
        }
    }
}
```

**Lý do dùng `IServiceScopeFactory`:** `BackgroundService` là singleton, `AppDbContext` là scoped — phải tạo scope mới cho mỗi lần chạy.

**Điều kiện xóa:**
- `ExpiresAt < cutoff`: hết hạn tự nhiên VÀ đã qua retention window.
- `RevokedAt < cutoff`: bị revoke chủ động VÀ đã qua retention window (tokens revoke gần đây vẫn cần cho audit/session list).

## Key Design Decisions

| Quyết định | Lý do |
|---|---|
| `ExecuteDeleteAsync` thay vì `repo.Delete()` per-row | Bulk DELETE SQL — không load rows vào memory, hiệu quả hơn nhiều ở scale lớn |
| `PeriodicTimer` thay vì `Task.Delay` | Không drift theo thời gian chạy, cancellable sạch hơn, .NET 6+ idiom |
| `RetentionDays = 7` default | Đủ để session management UI hiển thị lịch sử gần đây; đủ ngắn để không phình bảng |
| Không chạy ngay khi startup | `PeriodicTimer` chờ 1 interval đầu tiên → không gây load burst khi deploy |
| Đặt registration trong `AddPersistence` | Cleanup là persistence concern; cùng chỗ với DbContext và repository registration |
