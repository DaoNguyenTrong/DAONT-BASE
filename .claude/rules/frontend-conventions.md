# Frontend Conventions (`frontend/`)

Vue 3 + Vite + TypeScript, Pinia, naive-ui, Tailwind, vue-i18n. Package manager is `bun`. See `commands.md` for build/test/format commands.

## File & Naming Conventions

- Components/views: PascalCase, `*View.vue` suffix for route-level views (`frontend/src/views/OrganizationsView.vue`).
- Composables: kebab-case file, `use*` export (`frontend/src/composables/use-sidebar-menu.ts` → `useSidebarMenu`).
- Stores: kebab-case file, `use*Store` export via Pinia (`frontend/src/stores/auth.ts` → `useAuthStore`).
- No hand-written per-resource API modules — call the generated client directly (see API Layer below).
- Path alias `@/*` maps to `frontend/src/*` (`tsconfig.app.json`) — use it instead of relative `../../` chains.

## Components

Always `<script setup lang="ts">`. `ref`, `computed`, `reactive`, `defineStore`, `useI18n`, etc. are **auto-imported** (`unplugin-auto-import`, `unplugin-vue-components`) — do not manually import them, follow the existing files as the reference for what's auto-imported vs. not.

## Pinia Stores

Setup-store style only (function form, not options form):

```ts
export const useExampleStore = defineStore('example', () => {
  const value = ref<T | null>(null)
  const isReady = computed(() => value.value !== null)

  function setValue(next: T) {
    value.value = next
  }

  return { value, isReady, setValue }
})
```

## API Layer

`frontend/src/api/generated/**` (generated by `orval` from `shared/openapi/openapi.json` — see `api-contract.md`) is the only HTTP-calling layer; there is no hand-written `{resource}-api.ts` wrapper. Call the generated `get*()` factory directly:

```ts
import { getExamples } from '@/api/generated/examples/examples'

const client = getExamples() // call once per component/store, reuse the returned methods
const example = await client.examplesGetById(id)
```

- Never hand-roll another axios instance — every generated call already goes through `apiClient` (`api/mutator.ts`). A success side effect goes in the owning Pinia store, request/response types come from `api/types.ts` re-exports, int64 fields are normalized at the point of use: details in `api-contract.md`.
- In components, catch errors with `error instanceof ApiError` and prefer `error.problem.detail ?? error.problem.title`, falling back to a localized generic string (`t('errors.requestFailed')`) — see `ProfileDialog.vue` for the pattern.

## Runtime Configuration

Never read `import.meta.env.VITE_*` directly — call `getRuntimeConfig()` (`lib/runtime-config.ts`), which overlays the deploy-time `/config.json` over the build-time value key by key. Call it inside a function body or `<script setup>`, never at a `.ts` module's top level (that would freeze the value before `main.ts` has loaded `config.json`). The one deliberate exception is the axios instances in `api/client.ts`, whose `baseURL` `main.ts` re-applies right after loading `config.json` and before the first request. A new `VITE_*` value needs: the key in `RuntimeConfig`/`RUNTIME_CONFIG_KEYS`/`readBuildTimeDefaults`, `env.d.ts`, `public/config.example.json`, `docker/40-write-runtime-config.sh`, and the `web` service's `environment` in `docker-compose.prod.yml` + `.env.prod.example`.

A page that needs a permission declares it once as `meta.permission` (a `lib/permissions.ts` code) on its route: `useSidebarMenu` hides the item and the router guard sends a signed-in user without it to `home`. It is a UI gate only — the matching endpoint must still carry its `[Authorize(Policy = ...)]`. Never gate `home`, the fallback itself.

## Session and Organization Exits

Logout, session lapse and organization switch end with a **full page reload** (`lib/session-exit.ts` — `reloadToLogin()`/`reloadTo()`; `useOrganizationSwitch()`), never `router.replace`: Pinia stores live for the whole page, so in-SPA navigation would hand the previous account's/organization's state to whoever comes next. Don't add per-store reset logic — the reload covers stores added later too. Only the first exit per page takes effect, which is why the auth store's `logout()` reloads synchronously right after `clearAuth()` (before `App.vue`'s session-lapse watcher can redirect into the old page). A success toast before one of these exits won't survive it.

## Formatting & Linting

Prettier only (`frontend/.prettierrc.json`: no semicolons, single quotes, printWidth 100) — run `bun run --cwd frontend format`. ESLint runs **only the layer-boundary rules** (`frontend/eslint.config.js`, `bun run --cwd frontend lint:boundaries`): lib/api stay out of state and UI, stores stay out of UI, components never reach routed views or layouts. Do not add style or other rule sets without confirming with the user first — each one brings its own rules and CI implications.

## Testing

What to test and how to write it: `testing.md`. Tooling:

- Unit: Vitest + `@vue/test-utils`, mock HTTP with `msw`, mock Pinia state with `@pinia/testing`.
- E2E: Playwright (`frontend/e2e`), install browsers once via `bun run --cwd frontend test:e2e:install`.
