# PO Decisions

Rulings the product owner has made about **what the product does** — naming, scope boundaries,
accepted gaps, threshold and rule approvals. System-design trade-offs go in `.claude/decisions.md`
instead.

Written in {{PO_LANGUAGE}}, for a reader who doesn't read code: no class names, file paths or line
numbers. Newest entry at top. Log only what the PO actually ruled — in a PRD changelog, a tracker
comment, or in their own words — never an implementation judgment call.

Entry format:

```markdown
### YYYY-MM-DD — <the decision, in one line>

<What was decided and why, in a few sentences. The rejected alternative, if there was one.>
```
